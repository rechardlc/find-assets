# 项目规划

## 1. 项目概述

### 1.1 背景与痛点

在量化投资与日常盯盘中，「寻找大级别趋势拐点」与「捕捉均线粘合后的爆发临界点」是两套经典策略。项目以 A 股为起点，再扩展数字货币 USDT 永续：共享 EMA 指标与导出层，但**策略实现与数据源按市场隔离**。

| 痛点 | 说明 |
|------|------|
| 传统软件公式系统并发慢 | 通达信、同花顺等客户端公式无法高效全市场扫描 |
| 多周期联合筛选繁琐 | 周线 + 日线联动需大量手工配置 |
| 无法脱离客户端独立运行 | 难以集成到自动化流程或脚本 |

### 1.2 项目定位

一款面向**个人投资者或量化交易员**的本地化、高并发、多策略独立资产扫描工具。

### 1.3 项目目标

- 利用 Go 语言高并发优势，打造轻量级、零依赖选股可执行工具
- 默认覆盖全 A 股（沪深主板、创业板、科创板），保持现有 A 股入口不变
- 新增独立数字货币入口，覆盖 OKX USDT 永续热门山寨合约池
- A 股单次全量扫描耗时控制在 **15 秒以内**
- 支持 A 股 CLI 与 HTTP API 双模式，数字货币合约 CLI 独立运行
- 结果可导出 Console / JSON / Markdown

## 2. 核心功能需求

### A 股：周期 × 形态

通过 CLI / HTTP 自由组合：

- **周期（`-period` / `-p`）**：`day`（日线）/ `week`（周线），决定指标算在哪种 K 线上；
- **形态（`-pattern` / `-pt`）**：`pierce`（一箭穿心）/ `reversal`（超跌拐点），决定怎样才算命中。

二者交叉得到 4 种实用策略（`day:pierce`、`week:reversal`、`week:pierce`、`day:reversal`）。
下文「周线超跌拐点」「日线一箭穿心」是两组经典组合，其余组合复用同一套形态逻辑。

> 注册表另有 `15m` 周期名，但 A 股数据源只提供日线，HTTP 仅接受 `day`/`week`。数字货币的 `15m/1h/4h` 是交易所原生周期，走独立入口与参数（`-intervals` / `-pierce-intervals`），不要与 A 股 `-period` 混用。

### 2.1 形态：超跌拐点（`-pattern=reversal`，经典用法 `-period=week`）

**核心目的**：寻找长期下跌后，大级别动能衰竭、均线开始交叉复苏的左侧/右侧过渡标的。

**业务逻辑**：

1. **数据过滤**：拉取全 A 股历史 K 线，剔除退市、ST 及状态异常股票
2. **生命周期兼容**：
   - 老股（上市 ≥ 120 周）：计算 EMA5/10/30/60/120
   - 新股（60 周 ≤ 上市 < 120 周）：仅计算 EMA5/10/30/60
   - 上市不足 60 周：直接淘汰
3. **交叉窗口校验**：
   - 老股：最近 3 周内 EMA60 与 EMA120 发生过金叉或死叉
   - 新股：最近 3 周内 EMA30 与 EMA60 发生过金叉或死叉
4. **形态确认（当根）**：
   - 老股：EMA5 < EMA10 < EMA30 < EMA60 < EMA120（严格空头排列）
   - 新股：EMA5 < EMA10 < EMA30 < EMA60（严格空头排列）
5. **量能递减（拐点形成期）**：
   - 窗口取「死叉根 → 当根」共 4 根（默认 `-deadcross=3`）
   - 取前两根成交量的较大者为基准，与后两根串成序列：`max(前两根) > 倒数第二根 > 最后一根`，三者**严格递减**（不允许相等）
   - 意在过滤放量下杀的假拐点，只保留缩量下跌、卖压衰竭的标的；窗口不足 4 根时不做此约束

> 上述「周数」门槛为周线（`-period=week`）默认值；用于日线（`-period=day`）时按交易日近似放大
> （新股 ≥ 120 根、老股 ≥ 250 根、交叉窗口 5 根），由形态构造时按周期自动注入。
> **A 股逻辑不受数字货币模块影响**；数字货币拐点策略见 [数字货币合约扫描器设计](数字货币合约扫描器设计.md)。

### 2.2 形态：一箭穿心（`-pattern=pierce`，经典用法 `-period=day`）

**核心目的**：寻找均线高度缠绕、筹码极度集中后，主力资金暴力破局的多头启动点。

**业务逻辑**：

1. **数据过滤**：上市天数 ≥ 125 天（按交易日 K 线根数近似）
2. **均线粘合度评估**：
   - 计算 EMA5/10/30/60/120
   - `(MaxEMA - MinEMA) / MinEMA ≤ 2%`（可通过 `-range` 参数自定义，单位为百分比）
3. **K 线形态突破（一箭穿心）**：
   - 当天为阳线（Close > Open）
   - 收盘价 > MaxEMA 且 最低价 < MinEMA
4. **成交量放量**：
   - 当天成交量较前一日增加 > 3%（可通过 `-volume` 参数自定义，单位为百分比）

### 2.3 市场：数字货币 USDT 永续合约

**核心目的**：独立 CLI 在热门山寨合约上扫描多周期**拐点**与**一箭穿心**（与 A 股策略模块隔离）。

**业务逻辑**：

1. **市场入口独立**：`cmd/crypto-scanner`，不改变 A 股 `cmd/scanner` 默认行为；无 HTTP API
2. **策略独立**：`internal/crypto/reversal` + `pierce` + `amplitude` + `box`，**不修改** A 股 `internal/strategy`
3. **数据源**：OKX Public API（超时 + 退避重试 + `-rate` 全局限速）
4. **合约范围**：USDT 永续；排除 BTC、ETH、稳定币及异常合约；支持 `-custom` 本地列表
5. **热门池**：默认 `hot_alt`（振幅 / 涨跌幅 / 成交额 / 资金费率加权；缺项权重重分配）
6. **合约池缓存**：**每次进程启动**清除当日缓存并重新拉取；同日进程内后续扫描复用
7. **多周期调度**：调度表 = `-intervals`（拐点，默认 `15m,1h,4h`）∪ `-pierce-intervals`（一箭穿心，默认 `4h`）∪ `-amplitude-intervals`（振幅异动，默认 `4h`）∪ `-box-intervals`（箱体震荡，默认 `1h,4h`）；对齐收盘后延迟（默认 `20s`）；`-scan-on-start` 启动先扫一轮
8. **拐点**：交叉后第 2 根；超跌 + 超涨；无放量
9. **一箭穿心**：仅老币（≥250）；实体穿 4/5 线；上穿放量、下穿不放量；排列 + 粘合过滤；强势标记；与拐点同周期合并执行（K 线只拉一次）
9A. **振幅异动**：上一根已收盘 K 线 `(最高-最低)/最低 ≥ -amplitude`（默认 9%）；按实体方向分情绪涨/情绪跌；不过滤新币；≥2 倍阈值标记强势
9B. **箱体震荡**：最近 `-box-lookback`（默认 24）根已收盘 K 线内，≥ `-box-touches`（默认 3）根的最低价/最高价落在 `-box-pct`（默认 0.6%）带宽内，首末触及之间至少隔 `-box-min-gap`（默认 6）根中间 K 线，且末根仍贴着该价位；底部/顶部独立判定；触及 ≥5 次标记强势
10. **K 线不足**：1h/4h 整周期可跳过；单合约不足跳过该合约
11. **输出与通知**：exporter；命中时按「周期 × 策略」独立发邮件（`internal/notify`）

> 数字货币 K 线为交易所原生周期，不经 A 股日线重采样。

## 3. 非功能性需求

| 类别 | 要求 |
|------|------|
| 性能 | 5000+ 股票单次扫描 ≤ 15 秒 |
| 并发 | Goroutine + Channel，最大网络并发 80~100 |
| 数据 | 仅请求 600 根前复权日线，周线本地合成 |
| 交付 | 独立二进制，Windows / Linux 绿色运行 |
| 交互 | CLI 实时进度 + 命中清单；HTTP API + SSE 进度 |

数字货币补充要求：

| 类别 | 要求 |
|------|------|
| 数据源 | OKX 单一数据源（超时 + 退避重试） |
| 合约池 | 进程启动清当日缓存并重拉；同日进程内复用 |
| 调度 | 15m / 1h / 4h 多周期边界后延迟执行，默认延迟 20 秒 |
| 策略 | 独立 `crypto/reversal`（超跌+超涨）与 `crypto/pierce`（上穿+下穿一箭穿心），合并执行 |
| 隔离 | 独立 `crypto-scanner` 可执行文件，不影响 A 股扫描器 |

## 7. 风险与应对

| 风险 | 应对 |
|------|------|
| 数据源反爬限速 | 并发上限 100、UA 池、指数退避重试 |
| 未复权导致 EMA 失真 | 强制 `fqt=1` 前复权 |
| 当周未收盘周线为伪 K 线 | 文档说明，结果标注日期 |
| 停牌股数据缺口 | 用实际 K 线根数判定生命周期 |
| HTTP 重复触发打爆数据源 | 同时只允许 1 个扫描任务 |
| OKX 网络不可用 | HTTP 超时 + 对 429/5xx 退避重试；热门池整体失败则本轮报错退出 |
| 1h/4h K 线根数不足 | 跳过对应周期；单合约不足则跳过该合约 |
| 多周期 K 线未完全落库 | 对齐边界后延迟执行 |
| 山寨币波动剧烈 | 只输出扫描信号，不接交易账户、不自动下单 |
| 邮箱授权码泄露 | 不写入代码或仓库，优先使用环境变量 `FIND_ASSETS_SMTP_PASS` |
