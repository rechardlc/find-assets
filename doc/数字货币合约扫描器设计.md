# 数字货币合约扫描器设计

## 1. 背景

当前项目已经实现 A 股扫描器，核心能力包括：

- A 股清单拉取与本地日缓存
- 日线 / 周线周期抽象
- `pierce` / `reversal` 公共策略（**仅 A 股使用**）
- CLI 与 HTTP API 扫描入口
- JSON / Markdown / Console 导出

数字货币合约扫描器与 A 股**完全隔离**：独立命令入口、独立拐点策略模块（`internal/crypto/reversal`），不修改 A 股 `internal/strategy` 的任何判定逻辑（放量、第三根 K 线等保持不变）。

## 2. 目标

新增一个独立的 USDT 永续合约扫描器：

- 新增 `cmd/crypto-scanner`，不改动现有 `cmd/scanner` 的默认 A 股行为
- 使用 OKX USDT 永续合约数据（单一数据源，已移除 Binance）
- 每天第一次运行时生成热门山寨合约池缓存，同日后续运行复用缓存
- 合约池默认使用 `hot_alt` 综合热度，不单纯按交易量排序
- **同时监听 15m / 1h / 4h 三个 K 线周期**，各自对齐边界后延迟扫描，默认延迟 20 秒
- **专用拐点策略**（`reversal`）：超跌拐点 + 超涨拐点，死叉/金叉后第 2 根 K 线触发，**不做放量判断**
- **专用一箭穿心策略**（`pierce`，默认 1h / 4h，仅判定有 EMA120 的老币）：上穿 + 下穿，实体跨越 EMA5/10/30/60/120 中任意 4 根，上穿需放量、下穿不需；叠加方向排列与均线粘合过滤，穿满 5 根或穿 4 根且 EMA120 位于强势一侧时标记强势
- 拐点与一箭穿心**合并执行**：同一周期 K 线只拉取一次、同时判定两种策略，各自产出独立报告与邮件
- 输出沿用现有 exporter 体系
- 命中结果时默认通过 QQ 邮箱 SMTP 推送，**每个周期、每种策略独立发一封邮件**

## 3. 非目标

第一版不做以下事情：

- 不接交易账户，不下单
- 不做浏览器或 App 热搜抓取
- 不做 Web UI
- 不改造现有 A 股 HTTP API
- 不做盘中自动刷新合约池
- 不引入数据库
- 不复用 A 股 `internal/strategy/reversal` / `internal/strategy/pierce`（逻辑已分叉，crypto 独立实现）

## 4. 运行方式

示例：

```powershell
crypto-scanner.exe
```

不带参数时等价于：

```powershell
crypto-scanner.exe -source okx -pool hot_alt -top 200 -intervals 15m,1h,4h -pierce-intervals 1h,4h -schedule -delay 20s -scan-on-start
```

参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `source` | `okx` | 数字货币数据源（当前仅支持 okx） |
| `pool` | `hot_alt` | 合约池规则 |
| `top` | `200` | 每日缓存的候选合约数量 |

| `bars` | `300` | 每个合约拉取的 K 线数量 |
| `schedule` | `true` | 是否按周期持续扫描；单次扫描可传 `-schedule=false` |
| `delay` | `20s` | 各周期 K 线收盘后的延迟执行时间 |
| `workers` | `10` | 最大并发数 |
| `export` | `console` | 导出格式，复用 `console,json,md` |
| `out` | `./output` | 文件导出目录 |
| `mail` | `true` | 命中时发送邮件通知 |
| `mail-to` | `richard_0525@foxmail.com` | 邮件收件人 |

| `smtp-port` | `465` | SMTP 端口 |
| `smtp-user` | `richard_0525@foxmail.com` | SMTP 用户名 |
| `smtp-pass` | `FIND_ASSETS_SMTP_PASS` | SMTP 授权码，默认从 `.env` 或系统环境变量读取 |
| `env` | `.env` | 环境变量文件路径 |
| `custom` | `false` | 读取本地自定义数字货币列表 |

```powershell
crypto-scanner.exe -schedule=false
```

只监听部分周期：

```powershell
crypto-scanner.exe -intervals=15m,4h
```

## 5. 拐点策略（`internal/crypto/reversal`）

数字货币拐点策略与 A 股 `reversal` **独立实现**，主要差异如下：

| 维度 | A 股 `internal/strategy/reversal` | 数字货币 `internal/crypto/reversal` |
|------|-----------------------------------|-------------------------------------|
| 交叉后触发 | 第 3 根 K 线（`DeadCrossOffset=3`） | 第 2 根 K 线（`CrossOffset=2`） |
| 放量判断 | 有（缩量递减） | **无** |
| 方向 | 仅超跌（死叉 + 空头排列） | **超跌 + 超涨**（金叉 + 多头排列） |
| 周期 | day / week（及 15m 注册项） | **15m / 1h / 4h**（交易所原生 K 线） |
| 最少 K 线 | 按 A 股周期注入 | 新币 ≥ 120 根，老币 ≥ 250 根（按 K 线根数） |

判定**倒数第二根已收盘 K 线**（序列取 `last = len-2`）：末根为当前周期形成中的 K 线，不参与判定；`crossIdx = last - CrossOffset`。

### 5.1 超跌拐点（Oversold）

1. 相邻均线间距：EMA10-EMA30、EMA30-EMA60 ≥ 1%（避免粘合假信号）
2. 老币（≥ 250 根）：EMA60 在 `crossIdx` 处死叉 EMA120，当根严格空头排列（EMA5 < 10 < 30 < 60 < 120）
3. 新币（120~249 根）：EMA30 在 `crossIdx` 处死叉 EMA60，当根 EMA5 < 10 < 30 < 60
4. 当根须为死叉后**第 2 根** K 线（`crossIdx = last - 2`）

### 5.2 超涨拐点（Overbought）

与超跌对称：

1. 间距条件相同
2. 老币：EMA60 在 `crossIdx` 处**金叉** EMA120，当根严格多头排列
3. 新币：EMA30 在 `crossIdx` 处**金叉** EMA60，当根多头排列
4. 同样为交叉后第 2 根 K 线

### 5.3 K 线根数不足时的处理

| 周期 | 行为 |
|------|------|
| `15m` | `-bars` < 250 时报错；单合约返回 K 线 < 120 根时跳过该合约 |
| `1h` / `4h` | `-bars` < 120 时**跳过整个周期**（打日志，不报错）；单合约返回 K 线 < 120 根时跳过该合约 |

各周期互不影响：1h 根数不够只跳过 1h，15m / 4h 照常扫描。

### 5.4 扫描报告标识

- `Mode`：`15m:reversal` / `1h:reversal` / `4h:reversal`
- `Title`：`15分钟拐点` / `1小时拐点` / `4小时拐点`
- `Tag` 示例：`[1小时·超跌拐点·老币]`、`[4h·超涨拐点·新币]`

同一合约在同一周期内可能同时命中超跌与超涨（极罕见），会输出两条结果。

## 5A. 一箭穿心策略（`internal/crypto/pierce`）

数字货币一箭穿心与 A 股 `internal/strategy/pierce` **独立实现**，默认作用于 **1h / 4h**（可用 `-pierce-intervals` 调整；留空关闭）。

判定对象为**最新一根已收盘 K 线**（序列末尾为当前周期仍在形成中的 K 线，判定时取 `len-2`，即倒数第二根已收盘 K 线；末根不参与判定）。

### 5A.0 适用范围（仅老币）

- **只判定有 EMA120 的老币**（K 线 ≥ 250 根）；不足 250 根（无 EMA120）的新币**直接舍弃**，不再区分新/老币。

### 5A.1 方向与"穿越"定义（实体跨越）

| 方向 | 条件 |
|------|------|
| 上穿（`up`） | 阳线（收盘价 > 开盘价），被穿均线夹在 `(开盘价, 收盘价)` 之间 |
| 下穿（`down`） | 阴线（收盘价 < 开盘价），被穿均线夹在 `(收盘价, 开盘价)` 之间 |

"穿一根线" = 该 EMA 严格落在实体上下沿之间（即被 K 线实体整体跨过）。

### 5A.2 穿线根数

- 需穿 **EMA5 / EMA10 / EMA30 / EMA60 / EMA120 中任意 4 根**（5 选 4）。
- 少于 4 根：直接放弃。

### 5A.3 放量

- **上穿需放量**：当根成交量 > 前一根即可（无百分比阈值）
- **下穿不看放量**

### 5A.4 均线排列过滤（方向匹配，在最新根 len-1 判定）

以**最新根 `len-1`** 为结尾的最近 **5 根 K 线中至少 4 根**呈方向排列（EMA5/10/30/60/120 中任意 4 根呈严格排列）：

- 上穿 → 需**多头排列**（EMA5 > 10 > 30 > 60 > 120 方向）
- 下穿 → 需**空头排列**（EMA5 < 10 < 30 < 60 < 120 方向）

即「先在 `len-2` 穿心，下一根 `len-1` 仍维持方向排列」才算命中；不满足则放弃。

### 5A.5 均线粘合过滤（在穿心根 len-2 判定）

均线**极度粘合**时不判断多头/空头（视为无趋势）：穿心根 `len-2` 的相邻均线间距（EMA5-10 / 10-30 / 30-60 / 60-120）**全部**低于阈值即视为粘合并放弃。

| 周期 | 粘合阈值 |
|------|----------|
| `1h` | 各相邻间距 < 0.1% |
| `4h` | 各相邻间距 < 0.4% |

### 5A.6 强势标记（邮件高亮）

命中且满足下列任一 → 标记为**强势信号**：

- **穿满 5 根**均线，或
- **穿 4 根且 EMA120 位于强势一侧**：上穿 → EMA120 在实体下方；下穿 → EMA120 在实体上方。

标记效果：

- `Result.Alert = true`，`Tag` 追加 `·★强势`
- 邮件主题加 `【强势】` 前缀，正文对应行以 `★` 高亮

### 5A.7 判定对象（两根式）

- **穿心 / 粘合**：判定倒数第二根已收盘 K 线 `len-2`（实体跨越、放量、EMA120 强势位置、均线粘合均基于此根）。
- **排列**：判定最新根 `len-1`（当前周期形成中的 K 线）。
- 语义：先在 `len-2` 完成穿心（且该根未粘合），其**下一根 `len-1` 仍维持方向排列**，方才命中。

### 5A.8 扫描报告标识

- `Mode`：`1h:pierce` / `4h:pierce`
- `Title`：`1小时一箭穿心` / `4小时一箭穿心`
- `Tag` 示例：`[1小时·上穿·穿4线]`、`[4小时·下穿·穿4线·★强势]`、`[1小时·上穿·穿5线·★强势]`

同一合约同一周期可能同时命中上穿与下穿（极罕见），会输出两条结果。

## 6. 合约池规则

第一版实现 `hot_alt` 池，用公开接口可获取的字段计算综合热度。

过滤条件：

- 只保留 USDT 永续合约
- 只保留交易状态正常的合约
- 排除 BTC、ETH
- 排除稳定币或明显非山寨标的

综合分（四项指标先在池内做 min-max 归一化，再加权求和，避免量纲不一致导致某项失效）：

```text
raw = [ amplitude, abs(price_change_percent), log10(quote_volume), abs(funding_rate) ]
norm_j = (raw_j - min_j) / (max_j - min_j)          # 逐列归一化
hot_score = 100 * Σ (weight_j / Σweight_active) * norm_j
```

默认权重：振幅 `0.35`、涨跌幅 `0.25`、成交额 `0.30`、资金费率 `0.10`。

> 恒定列（`max == min`，例如 OKX 暂缺资金费率恒为 0）不参与打分，其权重按比例
> 重分配给其余活跃列，避免缺项被当 0 拉低整体分数。

字段来源（OKX 单一数据源）：

| 指标 | OKX 接口 |
|------|----------|
| 24h 高低价 / 涨跌幅 / 成交额 | `/api/v5/market/tickers?instType=SWAP` |
| 当前资金费率 | 暂未逐合约接入（`FundingRate` 恒为 0），后续补 `/api/v5/public/funding-rate` |
| K 线（15m / 1h / 4h） | `/api/v5/market/candles` |

OKX K 线周期参数映射：`1h` → `1H`，`4h` → `4H`（`15m` 原样传递）。

振幅计算：

```text
amplitude = (high24h - low24h) / open24h * 100
```

## 7. 缓存策略

每天第一次检索合约池时写入本地缓存：

```text
crypto/
  pools/
    hot_alt_20260704_okx.json
```

缓存内容：

```json
{
  "date": "2026-07-04",
  "exchange": "okx",
  "pool": "hot_alt",
  "contract": "usdt_perp",
  "top": 20,
  "generated_at": "2026-07-04T10:15:20+08:00",
  "assets": [
    {
      "symbol": "PEPEUSDT",
      "exchange_symbol": "PEPE-USDT-SWAP",
      "name": "PEPE USDT Perpetual",
      "base": "PEPE",
      "quote": "USDT",
      "exchange": "okx",
      "score": 86.3
    }
  ]
}
```

同日进程内有缓存时直接读取缓存，不再重新扫描全市场热门池；**每次进程重启会清除当日缓存并重新拉取**。各周期扫描共用同一份当日合约池，分别拉取对应周期 K 线。

## 8. 数据源

当前仅使用 OKX 单一数据源（已移除 Binance 及多源回退 `CompositeSource`）：

1. 从 OKX 拉取热门池和 K 线
2. HTTP 请求带 10s 超时；对网络错误、`429` 与 `5xx` 做最多 2 次指数退避重试
3. 全局限速器（默认 `-rate=15` 次/秒，令牌桶）约束所有并发请求，避免 `top` 较大时打爆限频
4. 单个合约 K 线拉取失败或 K 线为空时，该合约本轮跳过
5. 热门池整体拉取失败则本轮扫描报错退出

内部统一合约标识：

| 内部字段 | OKX |
|----------|-----|
| `Symbol` | 由 `BTC-USDT-SWAP` 归一化为 `BTCUSDT` |
| `ExchangeSymbol` | `BTC-USDT-SWAP` |
| `Exchange` | `okx` |

## 9. 定时扫描（多周期）

默认启用 `-schedule` 持续运行。程序为 **15m / 1h / 4h 各维护一个下次触发时间**，取最早时刻唤醒；同一时刻可能有多个周期同时到期（例如整点同时触发 15m 与 1h，4h 边界触发三个周期）。

```text
扫描时间 = 对应周期的下一个 K 线边界 + delay
```

15m 示例：

```text
09:00:20
09:15:20
09:30:20
09:45:20
```

1h 示例：

```text
09:00:20
10:00:20
11:00:20
```

4h 示例（本地时区对齐）：

```text
00:00:20
04:00:20
08:00:20
12:00:20
16:00:20
20:00:20
```

调度时间表取 `-intervals`（拐点）与 `-pierce-intervals`（一箭穿心）的**并集**；某周期到期时，该周期启用的所有策略在一次扫描中判定（K 线只拉一次），各策略独立 Report、导出、邮件。到期周期**顺序执行**。`-schedule=false` 时对并集周期各跑一轮后退出。

- 多周期边界延迟时间计算与 `DueIntervals`
- `crypto/reversal`：CrossOffset=2、无放量、超跌/超涨对称判定
- `crypto/pierce`：仅老币、实体跨越 4/5 线、上穿放量/下穿不放量、方向排列与粘合过滤、强势标记
- `1h/4h` 根数不足时跳过周期；一箭穿心根数不足时跳过该策略
- `RunScan` 合并执行两策略、各自报告字段

网络接口通过 `httptest.Server` 或注入 HTTP client 测试响应解析，不在单元测试中访问真实交易所。

## 13. 风险

| 风险 | 应对 |
|------|------|
| OKX 网络不可用 | HTTP 超时 + 对 429/5xx 退避重试；热门池整体失败则本轮报错退出 |
| 交易所字段变化 | 接口解析失败时返回明确错误 |
| 热门池一天内过时 | 第一版接受，后续可加 `refresh-pool` |
| 当前 K 线未收盘 | 对齐边界后延迟执行 |
| 1h/4h 新上市合约 K 线不足 | 跳过该合约；整周期 `-bars` 不足则跳过该周期 |
| 多周期同时到期 API 压力 | 顺序执行各周期扫描；workers 默认 10；全局限速（`-rate`）+ 退避重试 |
| 山寨币波动过大 | 输出信号，不做自动交易 |
| SMTP 授权码泄露 | 不写入代码或文档，优先使用环境变量 |
