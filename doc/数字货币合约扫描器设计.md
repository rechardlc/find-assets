# 数字货币合约扫描器设计

## 1. 背景

当前项目已经实现 A 股扫描器，核心能力包括：

- A 股清单拉取与本地日缓存
- 日线 / 周线周期抽象
- `pierce` / `reversal` 公共策略（**仅 A 股使用**）
- CLI 与 HTTP API 扫描入口
- JSON / Markdown / Console 导出

数字货币合约扫描器与 A 股**完全隔离**：独立命令入口、独立拐点策略模块（`internal/crypto/reversal`），不修改 A 股 `internal/strategy` 的任何判定逻辑（放量、第三根 K 线等保持不变）。

## 2. 目标

新增一个独立的 USDT 永续合约扫描器：

- 新增 `cmd/crypto-scanner`，不改动现有 `cmd/scanner` 的默认 A 股行为
- 优先使用 Binance USDT 永续合约数据，失败后回退 OKX USDT 永续合约数据
- 每天第一次运行时生成热门山寨合约池缓存，同日后续运行复用缓存
- 合约池默认使用 `hot_alt` 综合热度，不单纯按交易量排序
- **同时监听 15m / 1h / 4h 三个 K 线周期**，各自对齐边界后延迟扫描，默认延迟 20 秒
- **专用拐点策略**：超跌拐点 + 超涨拐点，死叉/金叉后第 2 根 K 线触发，**不做放量判断**
- 输出沿用现有 exporter 体系
- 命中结果时默认通过 QQ 邮箱 SMTP 推送，**每个周期独立发一封邮件**

## 3. 非目标

第一版不做以下事情：

- 不接交易账户，不下单
- 不做浏览器或 App 热搜抓取
- 不做 Web UI
- 不改造现有 A 股 HTTP API
- 不做盘中自动刷新合约池
- 不引入数据库
- 不复用 A 股 `internal/strategy/reversal`（逻辑已分叉）

## 4. 运行方式

示例：

```powershell
crypto-scanner.exe
```

不带参数时等价于：

```powershell
crypto-scanner.exe -source binance,okx -pool hot_alt -top 20 -intervals 15m,1h,4h -schedule -delay 20s
```

参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `source` | `binance,okx` | 数字货币数据源回退顺序 |
| `pool` | `hot_alt` | 合约池规则 |
| `top` | `20` | 每日缓存的候选合约数量 |
| `intervals` | `15m,1h,4h` | K 线周期列表，逗号分隔 |
| `bars` | `300` | 每个合约拉取的 K 线数量 |
| `schedule` | `true` | 是否按周期持续扫描；单次扫描可传 `-schedule=false` |
| `delay` | `20s` | 各周期 K 线收盘后的延迟执行时间 |
| `workers` | `10` | 最大并发数 |
| `export` | `console` | 导出格式，复用 `console,json,md` |
| `out` | `./output` | 文件导出目录 |
| `mail` | `true` | 命中时发送邮件通知 |
| `mail-to` | `richard_0525@foxmail.com` | 邮件收件人 |
| `mail-from` | `richard_0525@foxmail.com` | 邮件发件人 |
| `smtp-host` | `smtp.qq.com` | SMTP 服务器 |
| `smtp-port` | `465` | SMTP 端口 |
| `smtp-user` | `richard_0525@foxmail.com` | SMTP 用户名 |
| `smtp-pass` | `FIND_ASSETS_SMTP_PASS` | SMTP 授权码，默认从 `.env` 或系统环境变量读取 |
| `env` | `.env` | 环境变量文件路径 |
| `custom` | `false` | 读取本地自定义数字货币列表 |
| `custom-file` | `./crypto_symbols.txt` | 自定义列表路径，一行一个交易对 |

单次扫描全部周期：

```powershell
crypto-scanner.exe -schedule=false
```

只监听部分周期：

```powershell
crypto-scanner.exe -intervals=15m,4h
```

## 5. 拐点策略（`internal/crypto/reversal`）

数字货币拐点策略与 A 股 `reversal` **独立实现**，主要差异如下：

| 维度 | A 股 `internal/strategy/reversal` | 数字货币 `internal/crypto/reversal` |
|------|-----------------------------------|-------------------------------------|
| 交叉后触发 | 第 3 根 K 线（`DeadCrossOffset=3`） | 第 2 根 K 线（`CrossOffset=2`） |
| 放量判断 | 有（缩量递减） | **无** |
| 方向 | 仅超跌（死叉 + 空头排列） | **超跌 + 超涨**（金叉 + 多头排列） |
| 周期 | day / week（及 15m 注册项） | **15m / 1h / 4h**（交易所原生 K 线） |
| 最少 K 线 | 按 A 股周期注入 | 新股 ≥ 120 根，老股 ≥ 250 根（按 K 线根数） |

### 5.1 超跌拐点（Oversold）

1. 相邻均线间距：EMA10-EMA30、EMA30-EMA60 ≥ 1%（避免粘合假信号）
2. 老股（≥ 250 根）：EMA60 在 `crossIdx` 处死叉 EMA120，当根严格空头排列（EMA5 < 10 < 30 < 60 < 120）
3. 新股（120~249 根）：EMA30 在 `crossIdx` 处死叉 EMA60，当根 EMA5 < 10 < 30 < 60
4. 当根须为死叉后**第 2 根** K 线（`crossIdx = last - 2`）

### 5.2 超涨拐点（Overbought）

与超跌对称：

1. 间距条件相同
2. 老股：EMA60 在 `crossIdx` 处**金叉** EMA120，当根严格多头排列
3. 新股：EMA30 在 `crossIdx` 处**金叉** EMA60，当根多头排列
4. 同样为交叉后第 2 根 K 线

### 5.3 K 线根数不足时的处理

| 周期 | 行为 |
|------|------|
| `15m` | `-bars` < 250 时报错；单合约返回 K 线 < 120 根时跳过该合约 |
| `1h` / `4h` | `-bars` < 120 时**跳过整个周期**（打日志，不报错）；单合约返回 K 线 < 120 根时跳过该合约 |

各周期互不影响：1h 根数不够只跳过 1h，15m / 4h 照常扫描。

### 5.4 扫描报告标识

- `Mode`：`15m:reversal` / `1h:reversal` / `4h:reversal`
- `Title`：`15分钟拐点` / `1小时拐点` / `4小时拐点`
- `Tag` 示例：`[1小时·超跌拐点·老股]`、`[4h·超涨拐点·新股]`

同一合约在同一周期内可能同时命中超跌与超涨（极罕见），会输出两条结果。

## 6. 合约池规则

第一版实现 `hot_alt` 池，用公开接口可获取的字段计算综合热度。

过滤条件：

- 只保留 USDT 永续合约
- 只保留交易状态正常的合约
- 排除 BTC、ETH
- 排除稳定币或明显非山寨标的

综合分：

```text
hot_score =
  amplitude_score
+ abs_change_score
+ quote_volume_score
+ funding_abs_score
```

字段来源：

| 指标 | Binance | OKX |
|------|---------|-----|
| 24h 高低价 / 涨跌幅 / 成交额 | `/fapi/v1/ticker/24hr` | `/api/v5/market/tickers?instType=SWAP` |
| 当前资金费率 | `/fapi/v1/premiumIndex` | 第一版暂未逐合约接入，后续补 `/api/v5/public/funding-rate` |
| K 线（15m / 1h / 4h） | `/fapi/v1/klines` | `/api/v5/market/candles` |

OKX K 线周期参数映射：`1h` → `1H`，`4h` → `4H`（Binance 使用小写）。

振幅计算：

```text
amplitude = (high24h - low24h) / open24h * 100
```

## 7. 缓存策略

每天第一次检索合约池时写入本地缓存：

```text
crypto/
  pools/
    hot_alt_20260704_binance.json
```

缓存内容：

```json
{
  "date": "2026-07-04",
  "exchange": "binance",
  "pool": "hot_alt",
  "contract": "usdt_perp",
  "top": 20,
  "generated_at": "2026-07-04T10:15:20+08:00",
  "assets": [
    {
      "symbol": "1000PEPEUSDT",
      "exchange_symbol": "1000PEPEUSDT",
      "name": "1000PEPE USDT Perpetual",
      "base": "1000PEPE",
      "quote": "USDT",
      "exchange": "binance",
      "score": 86.3
    }
  ]
}
```

同日有缓存时直接读取缓存，不再重新扫描全市场热门池。各周期扫描共用同一份当日合约池，分别拉取对应周期 K 线。

## 8. 数据源回退

数据源顺序默认 `binance,okx`：

1. 优先从 Binance 拉取热门池和 K 线
2. Binance 热门池失败时，整体回退 OKX
3. Binance 单个 K 线失败时，可对该合约尝试 OKX 符号映射后回退
4. 两个数据源均失败时，该合约本轮跳过

内部统一合约标识：

| 内部字段 | Binance | OKX |
|----------|---------|-----|
| `Symbol` | `BTCUSDT` | 由 `BTC-USDT-SWAP` 归一化为 `BTCUSDT` |
| `ExchangeSymbol` | `BTCUSDT` | `BTC-USDT-SWAP` |
| `Exchange` | `binance` | `okx` |

## 9. 定时扫描（多周期）

默认启用 `-schedule` 持续运行。程序为 **15m / 1h / 4h 各维护一个下次触发时间**，取最早时刻唤醒；同一时刻可能有多个周期同时到期（例如整点同时触发 15m 与 1h，4h 边界触发三个周期）。

```text
扫描时间 = 对应周期的下一个 K 线边界 + delay
```

15m 示例：

```text
09:00:20
09:15:20
09:30:20
09:45:20
```

1h 示例：

```text
09:00:20
10:00:20
11:00:20
```

4h 示例（本地时区对齐）：

```text
00:00:20
04:00:20
08:00:20
12:00:20
16:00:20
20:00:20
```

到期周期**顺序执行**扫描（各周期独立 Report、导出、邮件）。`-schedule=false` 时对所有 `-intervals` 各跑一轮后退出。

```powershell

notepad .env
crypto-scanner.exe
```

`.env` 内容示例：

```text
FIND_ASSETS_SMTP_PASS=你的QQ邮箱授权码
```

默认配置：


## 11. 模块划分

```text
cmd/crypto-scanner/
  main.go          # CLI 入口、多周期调度、导出与邮件
  env.go           # .env 加载
  custom.go        # 自定义合约列表
internal/crypto/
  reversal/        # 数字货币专用拐点策略（超跌/超涨）
  interval.go      # 周期解析与 OKX 参数映射
  scheduler.go     # 单周期 / 多周期延迟调度
  service.go       # RunReversal 扫描编排
  exchange.go      # Binance / OKX 公开接口
  source.go        # Source 接口与 CompositeSource 回退
  pool.go          # hot_alt 评分
  cache.go         # 每日合约池缓存
  model.go         # Asset / Metric / PoolCache
internal/indicator/
  ema.go           # EMA、DeadCrossAt、GoldenCrossAt（与 A 股共用指标层）
internal/exporter/ # Console / JSON / Markdown
internal/notify/   # SMTP 邮件
```

| 文件 | 职责 |
|------|------|
| `cmd/crypto-scanner/main.go` | CLI 入口、参数解析、多周期 event loop |
| `internal/crypto/reversal/reversal.go` | 超跌/超涨拐点判定 |
| `internal/crypto/interval.go` | `15m,1h,4h` 解析；OKX `1H/4H` 映射 |
| `internal/crypto/scheduler.go` | `NextDelayedRun`、`InitSchedule`、`DueIntervals` |
| `internal/crypto/service.go` | 并发拉 K 线 + 双向拐点判定 + 组装 Report |
| `internal/crypto/exchange.go` | Binance / OKX REST 客户端 |
| `internal/crypto/source.go` | 数据源接口与 binance→okx 回退 |
| `internal/crypto/pool.go` | `hot_alt` 评分、排序、过滤 |
| `internal/crypto/cache.go` | 每日合约池缓存读写 |

## 12. 测试策略

优先覆盖纯逻辑：

- `hot_alt` 评分排序和主流币过滤
- Binance / OKX 符号归一化与 K 线周期映射
- 每日缓存命名、读取、过期处理
- 多周期边界延迟时间计算与 `DueIntervals`
- `crypto/reversal`：CrossOffset=2、无放量、超跌/超涨对称判定
- `1h/4h` 根数不足时跳过周期
- `RunReversal` 服务层报告字段

网络接口通过 `httptest.Server` 或注入 HTTP client 测试响应解析，不在单元测试中访问真实交易所。

## 13. 风险

| 风险 | 应对 |
|------|------|
| Binance 网络不可用 | 默认回退 OKX |
| 交易所字段变化 | 接口解析失败时返回明确错误 |
| 热门池一天内过时 | 第一版接受，后续可加 `refresh-pool` |
| 当前 K 线未收盘 | 对齐边界后延迟执行 |
| 1h/4h 新上市合约 K 线不足 | 跳过该合约；整周期 `-bars` 不足则跳过该周期 |
| 多周期同时到期 API 压力 | 顺序执行各周期扫描；workers 默认 10 |
| 山寨币波动过大 | 输出信号，不做自动交易 |
| SMTP 授权码泄露 | 不写入代码或文档，优先使用环境变量 |
