# 数字货币合约扫描器设计

## 1. 背景

当前项目已经实现 A 股扫描器，核心能力包括：

- A 股清单拉取与本地日缓存
- 日线 / 周线周期抽象
- `pierce` / `reversal` 公共策略（**仅 A 股使用**）
- CLI 与 HTTP API 扫描入口
- JSON / Markdown / Console 导出

数字货币合约扫描器与 A 股**完全隔离**：独立命令入口、独立拐点策略模块（`internal/crypto/reversal`），不修改 A 股 `internal/strategy` 的任何判定逻辑（放量、第三根 K 线等保持不变）。

## 2. 目标

新增一个独立的 USDT 永续合约扫描器：

- 新增 `cmd/crypto-scanner`，不改动现有 `cmd/scanner` 的默认 A 股行为
- 使用 OKX USDT 永续合约数据（单一数据源，已移除 Binance）
- **每次进程启动**清除当日热门山寨合约池缓存并重新拉取；同日进程内后续扫描复用缓存
- 合约池默认使用 `hot_alt` 综合热度，不单纯按交易量排序
- **同时监听 15m / 1h / 4h 三个 K 线周期**，各自对齐边界后延迟扫描，默认延迟 20 秒
- **专用拐点策略**（`reversal`）：超跌拐点 + 超涨拐点，死叉/金叉后第 2 根 K 线触发，**不做放量判断**
- **专用一箭穿心策略**（`pierce`，默认 1h / 4h，仅判定有 EMA120 的老币）：上穿 + 下穿，实体跨越 EMA5/10/30/60/120 中任意 4 根，上穿需放量、下穿不需；叠加方向排列与均线粘合过滤，穿满 5 根或穿 4 根且 EMA120 位于强势一侧时标记强势
- **专用振幅异动策略**（`amplitude`，默认 4h）：上一根已收盘 K 线振幅 ≥ 阈值（默认 9%）即命中，按实体方向区分情绪涨 / 情绪跌，用于捕捉情绪化的单边冲高或跳水
- **专用箱体震荡策略**（`box`，默认 1h / 4h）：最近 24 根已收盘 K 线内，至少 3 根的最低价（或最高价）落在 0.6% 带宽内、首末两次触及之间至少隔 6 根 K 线、箱体跨度内振幅 ≥ 5%，且末根仍贴着该价位，用于捕捉被反复验证的支撑 / 阻力
- 四种策略**合并执行**：同一周期 K 线只拉取一次、同时判定启用的策略，各自产出独立报告与邮件
- 输出沿用现有 exporter 体系
- 命中结果时默认通过 QQ 邮箱 SMTP 推送，**每个周期、每种策略独立发一封邮件**

## 3. 非目标

第一版不做以下事情：

- 不接交易账户，不下单
- 不做浏览器或 App 热搜抓取
- 不做 Web UI
- 不改造现有 A 股 HTTP API
- 不做盘中自动刷新合约池
- 不引入数据库
- 不复用 A 股 `internal/strategy/reversal` / `internal/strategy/pierce`（逻辑已分叉，crypto 独立实现）
- 振幅异动不做量能、均线、连续多根累计振幅等叠加过滤（第一版只看单根振幅）
- 箱体震荡不做量能确认、不判断突破方向、不预测箱体后续走向（只标记「这条支撑/阻力被反复验证、跨度内有真实波动且当前仍贴着」）

## 4. 运行方式

示例：

```powershell
crypto-scanner.exe
```

不带参数时等价于：

```powershell
crypto-scanner.exe -source okx -pool hot_alt -top 300 -intervals 15m,1h,4h -pierce-intervals 4h -amplitude-intervals 4h -amplitude 9 -box-intervals 1h,4h -box-pct 0.6 -box-lookback 24 -box-touches 3 -box-min-gap 6 -box-amplitude 5 -schedule -delay 20s -scan-on-start
```

参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `source` | `okx` | 数字货币数据源（当前仅支持 okx） |
| `pool` | `hot_alt` | 合约池规则 |
| `top` | `300` | 每日缓存的候选合约数量 |
| `intervals` | `15m,1h,4h` | 拐点策略 K 线周期列表，逗号分隔 |
| `pierce-intervals` | `4h` | 一箭穿心策略 K 线周期列表；留空则关闭一箭穿心 |
| `amplitude-intervals` | `4h` | 振幅异动策略 K 线周期列表，可多周期；留空则关闭振幅异动 |
| `amplitude` | `9` | 振幅异动阈值（百分比），须 > 0 |
| `box-intervals` | `1h,4h` | 箱体震荡策略 K 线周期列表，可多周期；留空则关闭箱体震荡 |
| `box-pct` | `0.6` | 箱体带宽上限（百分比），须 > 0 |
| `box-lookback` | `24` | 箱体震荡回看的已收盘 K 线根数，不得小于 `box-touches` |
| `box-touches` | `3` | 箱体最少触及次数，至少为 3 |
| `box-min-gap` | `6` | 首末两次触及之间的中间 K 线最少根数，至少为 1；`box-lookback` 须 ≥ 本值 + 2 |
| `box-amplitude` | `5` | 箱体跨度内振幅下限（百分比），须 > 0 |
| `bars` | `300` | 每个合约拉取的 K 线数量 |
| `schedule` | `true` | 是否按周期持续扫描；单次扫描可传 `-schedule=false` |
| `delay` | `20s` | 各周期 K 线收盘后的延迟执行时间 |
| `workers` | `10` | 最大并发数 |
| `export` | `console` | 导出格式，复用 `console,json,md` |
| `out` | `./output` | 文件导出目录 |
| `mail` | `true` | 命中时发送邮件通知 |
| `mail-to` | `richard_0525@foxmail.com` | 邮件收件人 |
| `mail-from` | `richard_0525@foxmail.com` | 邮件发件人 |
| `smtp-host` | `smtp.qq.com` | SMTP 服务器 |
| `smtp-port` | `465` | SMTP 端口 |
| `smtp-user` | `richard_0525@foxmail.com` | SMTP 用户名 |
| `smtp-pass` | `FIND_ASSETS_SMTP_PASS` | SMTP 授权码，默认从 `.env` 或系统环境变量读取 |
| `env` | `.env` | 环境变量文件路径 |
| `custom` | `false` | 读取本地自定义数字货币列表 |
| `custom-file` | `./crypto_symbols.txt` | 自定义列表路径，一行一个交易对 |
| `scan-on-start` | `true` | 定时模式下启动即先扫描一轮 |
| `rate` | `15` | OKX 请求全局限速（次/秒）；`<=0` 表示不限速 |

单次扫描全部周期：

```powershell
crypto-scanner.exe -schedule=false
```

只监听部分周期：

```powershell
crypto-scanner.exe -intervals=15m,4h
```

振幅异动改为 1h + 4h 双周期，阈值放宽到 12%：

```powershell
crypto-scanner.exe -amplitude-intervals=1h,4h -amplitude=12
```

箱体震荡只留更窄、被验证更多次、跨越时间更长、波动更大的箱体：

```powershell
crypto-scanner.exe -box-pct=0.4 -box-touches=4 -box-min-gap=10 -box-amplitude=8
```

## 5. 拐点策略（`internal/crypto/reversal`）

数字货币拐点策略与 A 股 `reversal` **独立实现**，主要差异如下：

| 维度 | A 股 `internal/strategy/reversal` | 数字货币 `internal/crypto/reversal` |
|------|-----------------------------------|-------------------------------------|
| 交叉后触发 | 第 3 根 K 线（`DeadCrossOffset=3`） | 第 2 根 K 线（`CrossOffset=2`） |
| 放量判断 | 有（缩量递减） | **无** |
| 方向 | 仅超跌（死叉 + 空头排列） | **超跌 + 超涨**（金叉 + 多头排列） |
| 周期 | day / week（及 15m 注册项） | **15m / 1h / 4h**（交易所原生 K 线） |
| 最少 K 线 | 按 A 股周期注入 | 新币 ≥ 120 根，老币 ≥ 250 根（按 K 线根数） |

判定**倒数第二根已收盘 K 线**（序列取 `last = len-2`）：末根为当前周期形成中的 K 线，不参与判定；`crossIdx = last - CrossOffset`。

### 5.1 超跌拐点（Oversold）

1. 相邻均线间距：EMA10-EMA30、EMA30-EMA60 ≥ 1%（避免粘合假信号）
2. 老币（≥ 250 根）：EMA60 在 `crossIdx` 处死叉 EMA120，当根严格空头排列（EMA5 < 10 < 30 < 60 < 120）
3. 新币（120~249 根）：EMA30 在 `crossIdx` 处死叉 EMA60，当根 EMA5 < 10 < 30 < 60
4. 当根须为死叉后**第 2 根** K 线（`crossIdx = last - 2`）

### 5.2 超涨拐点（Overbought）

与超跌对称：

1. 间距条件相同
2. 老币：EMA60 在 `crossIdx` 处**金叉** EMA120，当根严格多头排列
3. 新币：EMA30 在 `crossIdx` 处**金叉** EMA60，当根多头排列
4. 同样为交叉后第 2 根 K 线

### 5.3 K 线根数不足时的处理

| 周期 | 行为 |
|------|------|
| `15m` | `-bars` < 250 时报错；单合约返回 K 线 < 120 根时跳过该合约 |
| `1h` / `4h` | `-bars` < 120 时**跳过整个周期**（打日志，不报错）；单合约返回 K 线 < 120 根时跳过该合约 |

各周期互不影响：1h 根数不够只跳过 1h，15m / 4h 照常扫描。

### 5.4 扫描报告标识

- `Mode`：`15m:reversal` / `1h:reversal` / `4h:reversal`
- `Title`：`15分钟拐点` / `1小时拐点` / `4小时拐点`
- `Tag` 示例：`[1小时·超跌拐点·老币]`、`[4h·超涨拐点·新币]`

同一合约在同一周期内可能同时命中超跌与超涨（极罕见），会输出两条结果。

## 5A. 一箭穿心策略（`internal/crypto/pierce`）

数字货币一箭穿心与 A 股 `internal/strategy/pierce` **独立实现**，默认作用于 **1h / 4h**（可用 `-pierce-intervals` 调整；留空关闭）。

判定对象为**最新一根已收盘 K 线**（序列末尾为当前周期仍在形成中的 K 线，判定时取 `len-2`，即倒数第二根已收盘 K 线；末根不参与判定）。

### 5A.0 适用范围（仅老币）

- **只判定有 EMA120 的老币**（K 线 ≥ 250 根）；不足 250 根（无 EMA120）的新币**直接舍弃**，不再区分新/老币。

### 5A.1 方向与"穿越"定义（实体跨越）

| 方向 | 条件 |
|------|------|
| 上穿（`up`） | 阳线（收盘价 > 开盘价），被穿均线夹在 `(开盘价, 收盘价)` 之间 |
| 下穿（`down`） | 阴线（收盘价 < 开盘价），被穿均线夹在 `(收盘价, 开盘价)` 之间 |

"穿一根线" = 该 EMA 严格落在实体上下沿之间（即被 K 线实体整体跨过）。

### 5A.2 穿线根数

- 需穿 **EMA5 / EMA10 / EMA30 / EMA60 / EMA120 中任意 4 根**（5 选 4）。
- 少于 4 根：直接放弃。

### 5A.3 放量

- **上穿需放量**：当根成交量 > 前一根即可（无百分比阈值）
- **下穿不看放量**

### 5A.4 均线排列过滤（方向匹配，在最新根 len-1 判定）

以**最新根 `len-1`** 为结尾的最近 **5 根 K 线中至少 4 根**呈方向排列（EMA5/10/30/60/120 中任意 4 根呈严格排列）：

- 上穿 → 需**多头排列**（EMA5 > 10 > 30 > 60 > 120 方向）
- 下穿 → 需**空头排列**（EMA5 < 10 < 30 < 60 < 120 方向）

即「先在 `len-2` 穿心，下一根 `len-1` 仍维持方向排列」才算命中；不满足则放弃。

### 5A.5 均线粘合过滤（在穿心根 len-2 判定）

均线**极度粘合**时不判断多头/空头（视为无趋势）：穿心根 `len-2` 的相邻均线间距（EMA5-10 / 10-30 / 30-60 / 60-120）**全部**低于阈值即视为粘合并放弃。

| 周期 | 粘合阈值 |
|------|----------|
| `1h` | 各相邻间距 < 0.1% |
| `4h` | 各相邻间距 < 0.4% |

### 5A.6 强势标记（邮件高亮）

命中且满足下列任一 → 标记为**强势信号**：

- **穿满 5 根**均线，或
- **穿 4 根且 EMA120 位于强势一侧**：上穿 → EMA120 在实体下方；下穿 → EMA120 在实体上方。

标记效果：

- `Result.Alert = true`，`Tag` 追加 `·★强势`
- 邮件主题加 `【强势】` 前缀，正文对应行以 `★` 高亮

### 5A.7 判定对象（两根式）

- **穿心 / 粘合**：判定倒数第二根已收盘 K 线 `len-2`（实体跨越、放量、EMA120 强势位置、均线粘合均基于此根）。
- **排列**：判定最新根 `len-1`（当前周期形成中的 K 线）。
- 语义：先在 `len-2` 完成穿心（且该根未粘合），其**下一根 `len-1` 仍维持方向排列**，方才命中。

### 5A.8 扫描报告标识

- `Mode`：`1h:pierce` / `4h:pierce`
- `Title`：`1小时一箭穿心` / `4小时一箭穿心`
- `Tag` 示例：`[1小时·上穿·穿4线]`、`[4小时·下穿·穿4线·★强势]`、`[1小时·上穿·穿5线·★强势]`

同一合约同一周期可能同时命中上穿与下穿（极罕见），会输出两条结果。

## 5B. 振幅异动策略（`internal/crypto/amplitude`）

用于捕捉**情绪涨 / 情绪跌**：单根 K 线振幅过大，说明该周期内多空情绪失衡、出现单边冲高或跳水。默认作用于 **4h**（可用 `-amplitude-intervals` 调整，支持多周期；留空关闭）。

### 5B.1 判定对象

判定**上一根已收盘 K 线**（序列 `len-2`）；序列末尾 `len-1` 为当前周期仍在形成中的 K 线，不参与判定（与拐点、一箭穿心口径一致）。

### 5B.2 振幅公式与阈值

```text
amplitude = (最高价 - 最低价) / 最低价 * 100
```

- 达到 `-amplitude` 阈值（默认 `9`，即 9%）即命中
- 最低价 ≤ 0 或高低价倒挂（数据异常）时跳过该合约
- 与 `hot_alt` 合约池打分用的振幅**不是同一口径**：池打分用 24h `(high-low)/open`，本策略用单根 K 线 `(high-low)/low`

### 5B.3 情绪方向

| 方向 | 条件 | 标签 |
|------|------|------|
| `up` | 收盘价 > 开盘价 | 情绪涨 |
| `down` | 收盘价 < 开盘价 | 情绪跌 |
| `flat` | 收盘价 = 开盘价 | 情绪分歧（长上下影线来回扫针） |

方向由 K 线实体本身决定，因此同一合约同一周期**最多产出一条结果**（不像拐点/穿心需要双向各判一次）。

### 5B.4 适用范围（不过滤新币）

只需上一根 K 线自身的 OHLC，**不要求 EMA120、不过滤新上线合约**（最少 2 根 K 线即可判定）。新上线合约振幅天然巨大，属于该策略有意保留的情绪信号。

### 5B.5 强势标记（邮件高亮）

振幅 ≥ 阈值 × 2（默认 ≥ 18%）时标记为强势：`Result.Alert = true`，`Tag` 追加 `·★强势`，邮件主题加 `【强势】` 前缀。

### 5B.6 扫描报告标识

- `Mode`：`4h:amplitude` / `1h:amplitude`
- `Title`：`4小时振幅异动(≥9%)`（阈值随 `-amplitude` 变化）
- `Tag` 示例：`[4小时·情绪涨·振幅13.5%]`、`[4小时·情绪跌·振幅16.8%]`、`[4小时·情绪涨·振幅21.6%·★强势]`
- `Metric` 示例：`振幅 21.57%, 最高 30.94, 最低 25.45, 实体占比 88.7%`（实体占比 = 实体 / 振幅，用于区分单边推动与上下扫针）
- `Snapshot` 额外落 `high` / `low` / `amplitude`，便于 JSON 导出后核对

> 提示：4h + 9% 在山寨合约池上命中率不低（实测 60 个合约命中约 9 个）。若想只留极端情绪，调高 `-amplitude`。

## 5C. 箱体震荡策略（`internal/crypto/box`）

用于捕捉**被反复验证的支撑 / 阻力**（多重底 / 多重顶）：多根 K 线的最低价（或最高价）几乎踩在同一条水平线上，说明该价位有真实的买盘 / 卖盘。默认作用于 **1h / 4h**（可用 `-box-intervals` 调整，支持多周期；留空关闭）。

### 5C.1 判定对象与回看窗口

基准根为**上一根已收盘 K 线**（序列 `len-2`）；末尾 `len-1` 为当前周期形成中的 K 线，不参与判定（与其余策略口径一致）。回看窗口为以 `len-2` 结尾、最多 `-box-lookback` 根（默认 24）已收盘 K 线。

`-box-lookback` 只是窗口**上限**：历史不足的新上线合约按实际根数判定。单合约最少需要的根数取「触及次数」与「箱体跨度」两个需求的较大者再加 1 根形成中的末根，即 `max(box-touches, box-min-gap + 2) + 1`；默认参数下为 9 根。

### 5C.2 底部箱体（支撑）

在窗口内枚举箱体起点，令区间最低价为下沿 `L`：

```text
成员（一次「触及」）= 最低价落在 [L, L * (1 + box-pct%)] 的 K 线
命中 = 成员数 >= box-touches 且末根已收盘 K 线本身是成员
```

因为 `L` 取自区间最低价，「区间内不得跌破下沿」天然成立——一旦中间某根跌破，它就成为新的更低下沿，原成员被挤出带宽，触及次数自然不足。成员**不要求连续**，中间可以隔着远离箱体的 K 线。

### 5C.3 顶部箱体（阻力）

与底部完全对称，改用最高价，上沿 `H` 取区间最高价，成员区间为 `[H * (1 - box-pct%), H]`。

顶部与底部**独立判定**，同一合约同一周期可能同时命中（即真正的窄幅横盘），会输出两条结果。

### 5C.4 末根必须仍在箱体上

命中要求**末根已收盘 K 线本身是箱体成员**：箱体已经走完、价格脱离该价位时，信号视为过期，不再命中。这样每条命中都代表「当前正贴着一条被反复验证的支撑 / 阻力」。

### 5C.5 最小跨度门槛

**首次触及与末次触及之间至少隔 `-box-min-gap` 根中间 K 线**（默认 6，即含端点跨度 ≥ 8）：

```text
中间 K 线根数 = 末次触及下标 - 首次触及下标 - 1 >= box-min-gap
```

中间那些 K 线是不是成员**不作要求**，可以远离箱体。加这道门槛的原因是：只看触及次数时，连续三根挤在一起（例如 K 线 26/27/28 都踩 100.0 附近）也会命中，而这只是短暂停顿、不是被反复验证的支撑，实测命中量过大。要求跨越足够时间后价格重新回到同一价位，才说明该价位真的有承接 / 压制。

跨度不足的候选会被跳过，扫描继续往前扩展窗口寻找跨度足够的箱体——因此「三根紧挨着 + 一根在很早之前」这种组合仍可能命中，跨度按**真实首次触及**计算。

### 5C.6 箱体内振幅门槛

**箱体内的最高价与最低价至少相差 `-box-amplitude`**（默认 5%）：

```text
箱体内振幅 = (箱体内最高 High - 箱体内最低 Low) / 箱体内最低 Low >= box-amplitude%
```

「箱体内」= 首次触及那根到末根已收盘 K 线之间的**全部** K 线（即 `Metric` 里的「跨 N 根」）；最高价取这些 K 线里最高的 High、最低价取最低的 Low，**不是首末两根的价格、也不是箱体上下沿**——中间任意一根的冲高或杀跌都算。加这道门槛的原因是：带宽只约束下沿（或上沿）本身有多齐，一条价格全程贴着均价、上下都走不动的死水横盘同样能凑够触及次数，但支撑既没被真正来回考验、突破后也没有可交易空间。要求跨度内有 ≥ 5% 的来回摆动，留下的才是「有波动、且每次回落都被同一价位接住」的箱体。

与跨度门槛一样，振幅不足的候选会被跳过并继续往前扩展窗口；跨度越宽振幅只会越大，因此更早的起点仍可能达标。

### 5C.7 多个箱体成立时的取舍

同一方向上可能有多个起点都成立，先过跨度与振幅门槛，再取**触及次数最多**者（同一价位被验证越多越硬）；次数相同时取**起点最靠后**者，即最紧凑、最新鲜的箱体。

### 5C.8 强势标记（邮件高亮）

触及次数 ≥ 5 时标记为强势：`Result.Alert = true`，`Tag` 追加 `·★强势`，邮件主题加 `【强势】` 前缀。

### 5C.9 扫描报告标识

- `Mode`：`1h:box` / `4h:box`
- `Title`：`1小时箱体震荡(带宽≤0.6%·振幅≥5%·触及≥3次·间隔≥6根)`（随 `-box-pct` / `-box-amplitude` / `-box-touches` / `-box-min-gap` 变化）
- `Tag` 示例：`[1小时·底部箱体·触及3次·带宽0.40%]`、`[4小时·顶部箱体·触及5次·带宽0.28%·★强势]`
- `Metric` 示例：`箱体 1~1.004, 触及 3 次, 跨 19 根, 振幅 7.20%, 距下沿 0.50%`（跨 N 根 = 首次触及到末次触及的 K 线数，含端点；中间 K 线数 = N - 2）
- `Snapshot` 额外落 `low`（下沿）/ `high`（上沿）/ `range`（带宽百分比）/ `amplitude`（跨度内振幅百分比）/ `touches`（触及次数）

## 6. 合约池规则

第一版实现 `hot_alt` 池，用公开接口可获取的字段计算综合热度。

过滤条件：

- 只保留 USDT 永续合约
- 只保留交易状态正常的合约
- 排除 BTC、ETH
- 排除稳定币或明显非山寨标的

综合分（四项指标先在池内做 min-max 归一化，再加权求和，避免量纲不一致导致某项失效）：

```text
raw = [ amplitude, abs(price_change_percent), log10(quote_volume), abs(funding_rate) ]
norm_j = (raw_j - min_j) / (max_j - min_j)          # 逐列归一化
hot_score = 100 * Σ (weight_j / Σweight_active) * norm_j
```

默认权重：振幅 `0.35`、涨跌幅 `0.25`、成交额 `0.30`、资金费率 `0.10`。

> 恒定列（`max == min`，例如 OKX 暂缺资金费率恒为 0）不参与打分，其权重按比例
> 重分配给其余活跃列，避免缺项被当 0 拉低整体分数。

字段来源（OKX 单一数据源）：

| 指标 | OKX 接口 |
|------|----------|
| 24h 高低价 / 涨跌幅 / 成交额 | `/api/v5/market/tickers?instType=SWAP` |
| 当前资金费率 | 暂未逐合约接入（`FundingRate` 恒为 0），后续补 `/api/v5/public/funding-rate` |
| K 线（15m / 1h / 4h） | `/api/v5/market/candles` |

OKX K 线周期参数映射：`1h` → `1H`，`4h` → `4H`（`15m` 原样传递）。

振幅计算（仅用于合约池打分，与振幅异动策略的单根 K 线口径不同，见 5B.2）：

```text
amplitude = (high24h - low24h) / open24h * 100
```

## 8. 数据源

当前仅使用 OKX 单一数据源（已移除 Binance 及多源回退 `CompositeSource`）：

1. 从 OKX 拉取热门池和 K 线
2. HTTP 请求带 10s 超时；对网络错误、`429` 与 `5xx` 做最多 2 次指数退避重试
3. 全局限速器（默认 `-rate=15` 次/秒，令牌桶）约束所有并发请求，避免 `top` 较大时打爆限频
4. 单个合约 K 线拉取失败或 K 线为空时，该合约本轮跳过
5. 热门池整体拉取失败则本轮扫描报错退出

内部统一合约标识：

| 内部字段 | OKX |
|----------|-----|
| `Symbol` | 由 `BTC-USDT-SWAP` 归一化为 `BTCUSDT` |
| `ExchangeSymbol` | `BTC-USDT-SWAP` |
| `Exchange` | `okx` |

## 9. 定时扫描（多周期）

默认启用 `-schedule` 持续运行。程序为 **15m / 1h / 4h 各维护一个下次触发时间**，取最早时刻唤醒；同一时刻可能有多个周期同时到期（例如整点同时触发 15m 与 1h，4h 边界触发三个周期）。

```text
扫描时间 = 对应周期的下一个 K 线边界 + delay
```

15m 示例：

```text
09:00:20
09:15:20
09:30:20
09:45:20
```

1h 示例：

```text
09:00:20
10:00:20
11:00:20
```

4h 示例（本地时区对齐）：

```text
00:00:20
04:00:20
08:00:20
12:00:20
16:00:20
20:00:20
```

调度时间表取 `-intervals`（拐点）、`-pierce-intervals`（一箭穿心）、`-amplitude-intervals`（振幅异动）与 `-box-intervals`（箱体震荡）的**并集**；某周期到期时，该周期启用的所有策略在一次扫描中判定（K 线只拉一次），各策略独立 Report、导出、邮件。到期周期**顺序执行**。`-schedule=false` 时对并集周期各跑一轮后退出。

## 13. 风险

| 风险 | 应对 |
|------|------|
| OKX 网络不可用 | HTTP 超时 + 对 429/5xx 退避重试；热门池整体失败则本轮报错退出 |
| 交易所字段变化 | 接口解析失败时返回明确错误 |
| 热门池一天内过时 | 第一版接受，后续可加 `refresh-pool` |
| 当前 K 线未收盘 | 对齐边界后延迟执行 |
| 1h/4h 新上市合约 K 线不足 | 跳过该合约；整周期 `-bars` 不足则跳过该周期 |
| 多周期同时到期 API 压力 | 顺序执行各周期扫描；workers 默认 10；全局限速（`-rate`）+ 退避重试 |
| 山寨币波动过大 | 输出信号，不做自动交易 |
| 振幅异动命中过多导致邮件噪音 | 调高 `-amplitude`；或按周期收窄 `-amplitude-intervals`；★ 强势标记用于快速分层 |
| 箱体震荡在窄幅横盘行情下命中过多 | 已内置最小跨度门槛（`-box-min-gap`，默认 6）滤掉连续几根挤在一起的伪箱体，以及箱体内振幅门槛（`-box-amplitude`，默认 5%）滤掉贴着均价的死水横盘；仍嫌多可调低 `-box-pct`、调高 `-box-touches` / `-box-min-gap` / `-box-amplitude`，或按周期收窄 `-box-intervals`；★ 强势标记用于快速分层 |
| SMTP 授权码泄露 | 不写入代码或文档，优先使用环境变量 |
