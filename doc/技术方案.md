# 技术方案

本文以 **A 股扫描器**（`cmd/scanner`）为主。数字货币 USDT 永续的策略、调度、合约池与邮件见 [数字货币合约扫描器设计](数字货币合约扫描器设计.md)；运维见 [运维部署](运维部署.md)。

## 1. 总体架构

采用「**采集 → 合成/归一化 → 计算 → 策略 → 输出**」五层单向数据流。

- **A 股**：CLI 与 HTTP 共用 `ScanService`；策略在 `internal/strategy`（period × pattern）
- **数字货币**：独立 `cmd/crypto-scanner`；策略在 `internal/crypto/{reversal,pierce}`，**不复用** A 股 `strategy`；复用 `indicator` / `exporter` / `model` / `notify`

```
┌─────────────────────────────────────────────┐
│            Entrypoint (cmd/scanner)         │
│   ┌───────────────┐    ┌────────────────┐   │
│   │  CLI 模式     │    │  HTTP 模式      │   │
│   │ -p/-pt/-so …  │    │ -s -a :8080    │   │
│   └──────┬────────┘    └────────┬───────┘   │
│          └─────────┬─────────────┘          │
│                    ▼                        │
│         ┌──────────────────┐                │
│         │   ScanService    │                │
│         └─────────┬────────┘                │
│                   ▼                         │
│  Source(Composite) → Scanner → Strategy     │
│     (日缓存)          ↓                     │
│              Period.Resample → Pattern.Eval │
│                   ▼                         │
│         ┌──────────────────┐                │
│         │    Exporter      │                │
│         │ Console/JSON/MD  │                │
│         └──────────────────┘                │
└─────────────────────────────────────────────┘
```

数字货币入口与上图并列、互不共享策略层；链路摘要：OKX → `RunScan(reversal|pierce)` → 多周期调度 → exporter + notify。细节见专文。

### 1.1 A 股调用链

```text
cmd/scanner
  → PrepareStockCache()                 # stocks/ 按日清单缓存
  → source.NewComposite(spec)           # auto|em|sina|tencent|file
  → service.ScanService.Run
       → strategy.Get(period, pattern)
       → src.ListAll
       → scanner.Run
            → DailyKlines → Match
                 → Period.Resample (day 恒等 / week→ToWeekly)
                 → Pattern.Eval (pierce|reversal → EMA)
       → exporter.Report
  → exporter.Write (console/json/md)

HTTP(-serve)：同一 ScanService → Gin /api/v1/*
```

## 3. 模块设计

### 3.1 数据源（Source）

**接口**：

```go
type Source interface {
    ListAll(ctx context.Context) ([]model.Stock, error)
    DailyKlines(ctx context.Context, stock model.Stock, n int) ([]model.Kline, error)
}
```

**实现与回退**（`Composite`，`-source` 默认 `auto`）：

| 取值 | 行为 |
|------|------|
| `auto` | `em → sina → tencent` |
| `em` / `eastmoney` | 东方财富 |
| `sina` | 新浪 |
| `tencent` / `tx` | 腾讯（清单仍可回退新浪） |
| `file:./path.json` | 本地清单；可与远程源逗号串联，如 `file:./stocks.json,em` |

东财接口要点：

| 用途 | URL | 关键参数 |
|------|-----|----------|
| 股票清单 | `80.push2.eastmoney.com/api/qt/clist/get` | `fs` 沪深 A 股全集 |
| K 线历史 | `push2his.eastmoney.com/api/qt/stock/kline/get` | `klt=101` 日线，`fqt=1` 前复权，`lmt=600` |

**过滤规则**（`filter.go`）：

- 保留：60/000/001/002/003（主板）、300/301（创业板）、688/689（科创板）
- 剔除：ST/*ST/退市、B 股、北交所、ETF/指数

**清单日缓存**（`stock_cache.go`，仅 CLI）：

- 路径：可执行文件旁 `stocks/stocks_YYYYMMDD.json`
- 同日复用；跨日清理旧文件并重新拉取

**HTTP 客户端优化**（东财等）：

- `MaxIdleConnsPerHost: 300`
- 超时 8s，最多重试 2 次，指数退避 + jitter
- User-Agent 池轮换

### 3.2 K 线合成（Aggregator）

**设计原则**：只向服务器请求前复权日线（默认 600 根），周线在本地合成。

**算法**：按 ISO 周编号分组（周一为一周起点）

| 字段 | 规则 |
|------|------|
| Open | 该周第一个交易日开盘价 |
| Close | 该周最后一个交易日收盘价 |
| High | 该周最高价 |
| Low | 该周最低价 |
| Volume | 该周成交量累加 |

当周未收盘时，最后一根周线为「伪 K 线」，符合策略「含当周」语义。

### 3.3 技术指标（Indicator）

**EMA 递推公式**：

```
alpha = 2 / (N + 1)
EMA[i] = alpha * Close[i] + (1 - alpha) * EMA[i-1]
```

冷启动：`EMA[0] = Close[0]`。

**交叉判定**（`Cross`）：在 `[from, to]` 闭区间内，若 `a[i-1] - b[i-1]` 与 `a[i] - b[i]` 符号相反，则判定发生过金叉或死叉。

**精确交叉点**（亦被数字货币拐点策略使用）：

- `DeadCrossAt(fast, slow, i)`：索引 `i` 处 fast 下穿 slow
- `GoldenCrossAt(fast, slow, i)`：索引 `i` 处 fast 上穿 slow

### 3.4 选股策略（Strategy = 周期 × 形态）

- **Period**：把原始日线重采样成目标周期
- **Pattern**：对已是目标周期的 K 线做命中判定

```go
type Period interface {
    Name() string                               // "15m" / "day" / "week"
    Label() string
    Resample(daily []model.Kline) []model.Kline // 15m/day 恒等，week → ToWeekly
}

type Pattern interface {
    Name() string  // "pierce" / "reversal"
    Label() string
    Eval(stock model.Stock, bars []model.Kline) (model.Result, bool)
}

type Strategy interface {
    Period() string
    Pattern() string
    Mode() string    // "day:pierce"
    Title() string
    Match(stock model.Stock, daily []model.Kline) (model.Result, bool)
}
```

`Match` = `Period.Resample(daily)` → `Pattern.Eval(bars)`。

构造：`strategy.Get(period, pattern, opt)`。

实用组合（HTTP 与 CLI）：`day|week` × `pierce|reversal`。

> 注册表含 `15m`（恒等透传），供扩展；A 股源仅有日线，HTTP `oneof=day week` 拒绝 `15m`。

> A 股 `reversal`：含放量、死叉后第 N 根（默认 `-deadcross=3`）。数字货币拐点见专文，不共用本包。

> **阈值随周期而变**：`pierce` 的 `MinBars`、`reversal` 的 `MinBarsNew/OldBars` 等由 `newPierce(period)` / `newReversal(period)` 注入；`Range`、`Volume`、`DeadCross` 可经 `Options` / CLI / HTTP 覆盖。

**命中结果**：

```go
type Result struct {
    Code, Name, Tag, Metric string
    Snapshot Snapshot  // EMA、粘合度、Bars、Alert 等
}
```

### 3.5 并发扫描器（Scanner）

信号量 Channel + WaitGroup + 原子计数：

```
for each stock:
    sem <- struct{}{}
    go func() {
        klines := src.DailyKlines(stock, bars)
        if strat.Match(stock, klines) { out <- result }
        progress(done, total)
    }()
```

- 默认并发：100
- 结果按代码排序
- `ProgressFn` 供 CLI 与 SSE

### 3.6 业务编排（ScanService）

统一：拉清单 → 并发扫描 → 组装 `exporter.Report`。CLI 与 HTTP 均调用 `Run()`。

### 3.7 结果导出（Exporter）

| 格式 | 说明 |
|------|------|
| `console` | 控制台文本 |
| `json` | 结构化报告 |
| `md` | Markdown 表格 |

```go
type Report struct {
    TaskID, Period, Pattern, Mode, Title, Elapsed string
    StartedAt, FinishedAt time.Time
    Total, Matched int
    Results []model.Result
}
```

A 股与数字货币共用 exporter；后者另接 `notify` 发邮件。

### 3.8 HTTP 服务（Gin）

- 异步：`TaskStore` 内存，`task_id` 查询
- SSE：`/api/v1/scans/:id/stream`
- 限流：同时 1 个扫描任务
- 优雅关闭：`Shutdown` + 5s
- 请求体支持 `dead_cross`（reversal）

接口字段见 [API 接口](API接口.md)。数字货币无 HTTP 入口。

## 4. 数据流

```
1. ListAll()              → []Stock (~5300)
2. DailyKlines(code)      → []Kline (前复权日线)
3. Period.Resample(daily) → day 恒等 / week 合成
4. EMA(closes, N)         → []float64
5. Pattern.Eval(bars)     → Result | false
6. Exporter.Write()       → console / json / md
```

## 5. 性能设计

| 项目 | 数值 |
|------|------|
| 股票总数 | ~5300 |
| 单次 HTTP 平均耗时 | 150~300 ms |
| 并发数 | 100 |
| 理论耗时 | 5300 / 100 × 0.25 ≈ 13 s |
| CPU（EMA） | < 1 s |

**瓶颈在网络**：放大 `MaxIdleConnsPerHost`、Keep-Alive；清单已有按日文件缓存。

## 6. 前复权与数据校验

| 问题 | 处理 |
|------|------|
| 除权日 EMA 失真 | 强制 `fqt=1` 前复权 |
| 前复权后负价 | `Close <= 0` 跳过 |
| 停牌占位符 `"-"` | `parseFloat` → 0 并过滤 |
| 次新股 K 线不足 | `len(klines) < 阈值` 淘汰 |
